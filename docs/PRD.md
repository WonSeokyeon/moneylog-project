> **버전** 1.3 · **최종 수정** 2026-09-18
> 이 문서는 "무엇을 만드는가"를 정의한다. "어떻게 만드는가"는 `CLAUDE.md`, "언제 만드는가"는 `ROADMAP.md`를 참조한다.
>
> **완료 판정 기준은 `ROADMAP.md`의 검증 체크리스트가 정본이다.** 이 문서는 요구사항 정의만 담는다.

## 1. 배경과 목표

### 배경

가계부를 쓰겠다고 마음먹은 사람이 실제로 마주치는 선택지는 둘이다.

- **수기 또는 엑셀** — 자유롭지만 매번 표를 만들고 수식을 고쳐야 하고, 달이 바뀌면 시트를 복사한다. 몇 달 지나면 열이 어긋나 있다.
- **기존 가계부 앱** — 입력은 편하지만 계좌 연동 권한을 요구하거나, 광고와 부가 기능이 많아 "얼마 썼는지"를 확인하기까지 화면을 여러 번 거친다.

그리고 두 선택지 모두 **기록만 남기고 끝난다.** 석 달치 데이터가 쌓여 있어도 "이번 달 이 속도면 얼마 쓸까"에 답해주지 않는다. 사용자는 계산을 직접 해야 하고, 대부분은 하지 않는다.

기록의 마찰을 최소로 줄이면서, **쌓인 데이터가 스스로 답을 내놓는** 개인용 가계부에 공백이 있다.

### 목표

1. **수입·지출 한 건을 3초 안에** 기록할 수 있게 한다. 페이지 이동 없이 목록 화면에서 바로 입력한다.
2. 쌓인 데이터로 **이번 달 예상 지출을 자동 계산**해 보여준다. 사용자가 아무것도 설정하지 않아도 동작한다.
3. **고정지출(구독·월세 등)을 사용자가 등록하지 않아도 데이터에서 찾아낸다.**
4. 기존 엑셀 가계부를 **CSV로 그대로 들여오고, 언제든 되가져갈 수 있게** 한다.
5. 웹/모바일 반응형으로 브라우저 하나만 있으면 쓸 수 있게 한다.

### 비목표 (이번 범위 아님)

- **배포** — 로컬 개발 완료까지가 이번 범위다. 배포 여부와 방식은 미정
- 구글 등 소셜 로그인
- 오픈뱅킹·카드사 계좌 연동
- 반복 거래 자동 등록 (「고정지출 자동 감지」가 같은 문제를 푼다)
- **CSV 가져오기 중복 검사** — 같은 파일을 두 번 올리면 거래가 두 번 등록된다. 가져오기가 1회성(엑셀 이전)이고 4.4가 「실패분만 골라 다시 올림」이라는 부분 재업로드를 전제하므로, 해시 기반 중복 제거 대신 화면 안내로 처리한다
- 다중 통화, 환율
- 자산/부채 관리, 순자산 추적, 투자 기록
- 가족·커플 공유 가계부
- 알림/푸시
- 모바일 네이티브 앱

## 2. 대상 사용자

| 구분 | 설명 |
|---|---|
| 주 사용자 | 혼자 생활비를 관리하는 20~40대. 엑셀 가계부를 써봤거나 가계부 앱을 쓰다 그만둔 경험이 있다 |
| 사용 환경 | 입력은 모바일 브라우저, 확인·분석은 데스크톱 브라우저 |
| 기술 수준 | 웹 서비스 사용에 익숙. 엑셀을 다뤄본 적이 있다 |

**핵심 시나리오**

> "점심을 먹고 나오면서 휴대폰으로 금액만 치고 '식비' 버튼을 눌러 저장한다. 3초. 주말에 노트북으로 대시보드를 열어 이번 달 이 속도면 얼마를 쓰게 될지, 어느 카테고리가 평소보다 튀었는지 확인한다."

**이탈 지점에 대한 전제**

가계부 앱이 실패하는 지점은 기능 부족이 아니라 **입력 귀찮음**이다. 사용자는 사흘 쓰다 멈추고, 데이터가 없으니 분석 기능도 무의미해진다. 따라서 이 제품에서 **가장 중요한 화면은 대시보드가 아니라 입력 폼**이며, 요구사항 우선순위도 그 기준으로 정한다.

## 3. 기능 요구사항

**우선순위 정의** — **P0**: MVP 필수(전부 구현해야 완료) · **P2**: 범위 밖 기록

> **P1(있으면 좋음)은 쓰지 않는다.** MVP 범위에서 "있으면 좋은" 항목은 결국 만들지 않으면서 완료 판정만 흐린다. 그런 항목은 9장 「향후 확장 후보」로 옮긴다.

> 아래 P0 항목은 `ROADMAP.md`의 Phase 작업과 1:1로 대응한다. P0를 빼고 완료 처리하지 않는다.

### 3.8 챗봇 조회 (CHAT)

```
/dashboard 진입 (이번 달)
```

```
/data → "CSV 가져오기" → 파일 선택 → 업로드
```

### 5.1 전역 적용 요구사항 (모든 화면 공통)

> 특정 화면 하나에 속하지 않는 요구사항이다. 화면별 절에 중복 기술하지 않고 여기에만 둔다.

**공통 헤더** (인증이 필요한 모든 화면)
- 닉네임 표시, 네비게이션(대시보드 · 내역 · 예산 · 설정), 로그아웃 버튼 — `AUTH-06`, `AUTH-08`. 닉네임을 누르면 변경 팝업이 열린다 — `AUTH-10`
- 로그아웃: 토큰 삭제 + React Query 캐시 초기화 → `/login` 이동. **서버 API 호출 없음**
- 모바일에서는 네비게이션을 하단 탭 바로 전환한다

**라우트 보호** — `AUTH-07`
- 토큰이 없거나 **만료된** 상태로 보호된 화면 접근 시 `/login`으로 이동
- 토큰 문자열의 존재 여부가 아니라 **`exp` 클레임을 디코드해 판정**한다. 만료 토큰이 판정을 통과하면 보호 화면이 401 왕복 동안 노출된다
- 인증 판정이 끝나기 전에는 스켈레톤을 보여준다
- API 응답이 401이면 자동 로그아웃 처리

**소유권 · 404** — `TXN-12`, `CAT-05`
- 타인 소유이거나 존재하지 않는 리소스는 서버가 404로 응답한다(존재 여부를 노출하지 않음)
- 화면은 목록으로 자동 리다이렉트하지 않고 "찾을 수 없습니다" 상태를 보여준다

**금액 표시 · 입력** — `TXN-04`, `UX-08`
- 표시: 천단위 콤마 + `tabular-nums`. 수입은 초록(`#10B981`), 지출은 빨강(`#EF4444`)
- 입력: `<input type="number">`를 쓰지 않는다. 콤마가 들어가면 값이 사라지기 때문이다 (`CLAUDE.md` 8장)
- 포맷·파싱은 `lib/money.ts` 한 곳에서만 수행한다

**날짜 기준** — `STAT-01`, `STAT-04`
- 조회 대상 월(`yearMonth`)과 사용자의 오늘(`asOf`)은 **클라이언트가 서버로 보낸다.** 서버가 `now()`로 추론하지 않는다
- 서버는 UTC로 돌기 때문에, 서버가 판정하면 매월 1일 0~9시에 사용자가 지난달 대시보드를 보게 된다 (`CLAUDE.md` 4장)

**반응형** — `UX-05`
- 360px ~ 1920px에서 레이아웃이 깨지지 않는다
- 컨테이너 `max-w-5xl`, 패딩 모바일 16px · 데스크톱 24px
- 퀵 입력 바는 데스크톱에서 한 줄, 모바일에서 세로로 쌓인다

**접근성** — `UX-06`
- 모든 입력에 label이 연결되어 있다
- **거래 입력을 키보드만으로 완주할 수 있다.** Tab 순서가 금액 → 카테고리 → 날짜 → 저장으로 이어지고, Enter로 저장된다

**다크 모드** — `UX-07`, `UX-09`
- 디자인 토큰을 라이트/다크 양쪽으로 정의한다. 기본값은 `prefers-color-scheme`(OS 설정)을 따른다
- **헤더의 아이콘 버튼으로 사용자가 직접 전환할 수 있다** — `UX-09`. 선택값은 `localStorage`에 저장되어 재방문 시 유지된다
- 카테고리 색은 사용자가 지정한 값이므로 다크 모드에서도 그대로 쓴다. 대신 **텍스트는 색 위에 올리지 않고 색 옆에 둔다**(대비 계산이 불가능하기 때문)

**챗봇 위젯** — `CHAT-01` ~ `CHAT-12`
- 화면 우하단 플로팅 버튼으로 열고 닫는다. 새 화면이나 라우트를 만들지 않는다. 버튼을 끌어 화면 안 원하는 곳으로 옮길 수 있고(패널이 함께 따라간다), 패널은 좌상단 핸들을 끌어 크기를 조절할 수 있다
- 규칙 기반 키워드 매칭이다. LLM을 호출하지 않고, 이미 구현된 조회 API(월별 통계·거래 목록·고정지출)만 재사용한다
- 질문을 이해하지 못하면 지원하는 질문 예시를 안내한다("이해하지 못했어요"류의 막다른 응답을 주지 않는다)

#### 챗봇 규칙 (정본)

> 이 절이 챗봇 동작의 정본이다. `lib/chat/intents.ts`·`answers.ts`는 이 표를 그대로 구현한다. 규칙을 바꾸면 이 절을 먼저 고친다.

**R1. 입력 정규화** — `CHAT-12`
1. 앞뒤 공백을 자르고, **키워드 비교는 공백을 모두 지운 문자열끼리** 한다. "고정 지출"과 "고정지출", "이번 주"와 "이번주"는 같다
2. **오타는 자모 1개 차이까지 허용**한다("지촐"→"지출", "예샨"→"예산"). 한글을 초성·중성·종성으로 풀어 편집 거리 1 이내면 같은 단어로 본다
   - **1음절 키워드("총", "썼", "튀")는 오타를 허용하지 않는다.** 자모 1개 차이면 거의 모든 글자와 겹쳐 오탐이 난다. 자주 틀리는 형태는 키워드에 직접 넣는다("썻")
   - **다른 등록 키워드와 정확히 일치하는 부분에는 오타 보정을 적용하지 않는다.** "예상"과 "예산"은 자모 1개 차이라, 이 규칙이 없으면 "이번달 예상 지출"이 예산 질문이 된다
   - **날짜·기간 표현(오늘·어제·지난달 등)에는 오타 보정을 적용하지 않는다.** "오는 길에"가 "오늘"로 읽히면 엉뚱한 날짜의 숫자를 자신 있게 답하게 된다. 틀린 숫자보다 "이해 못 함"이 낫다
3. 조사("지출은", "지출이")와 어순("얼마 썼어 식비" / "식비 얼마 썼어")은 따로 처리하지 않는다 — 부분 문자열 비교라 원래 영향을 받지 않는다
4. **카테고리 이름**: 기호를 빼고 비교하고(`주거/통신` = `주거통신`), `/`로 나뉜 이름은 앞뒤 각각(2글자 이상)도 이름으로 인정한다("통신비 얼마" → `주거/통신`). 여러 카테고리가 걸리면 **정확히 일치한 것 → 긴 이름** 순으로 고른다(`기타수입`이 `기타`보다 먼저)

**R2. 기간 해석** — `CHAT-09`, `CHAT-10`, `CHAT-12`
| 표현 | 해석 |
|---|---|
| 없음 | 이번 달(목록 질문은 전체 기간) |
| 이번달 · 이달 | 이번 달 |
| 지난달 · 저번달 · 전월 | 이번 달 - 1 |

| 오늘 · 어제 · 그제(그저께) | 그 날짜 |
| `9월 14일` | 그 날짜(연도 규칙은 위와 같음) |
| 이번주 · 지난주 · 최근 N일 | 그 구간(목록 질문에서만) |
- 연도를 명시해 **미래 달**을 물으면(예: 9월에 "2027년 1월") 조회하지 않고 "아직 오지 않은 달이에요"를 답한다
- "3개월"처럼 숫자와 `월` 사이에 다른 글자가 끼면 월 표현으로 보지 않는다

**R3. 의도 판정 우선순위** — 위에서부터 검사해 **먼저 맞는 것 하나만** 쓴다
| 순위 | 의도 | 트리거 | 비고 |

| 3 | 고정지출 `CHAT-05` | 고정지출 · 정기결제 · 구독 · 자동이체 · 매달 나가 | |
| 4 | 예산 `CHAT-05` | 예산 | 카테고리를 함께 말하면 그 카테고리만 |

| 11 | 수입 카테고리 | 수입 카테고리 이름(급여 등) | 월별 통계의 카테고리 집계는 지출 전용이라 **목록으로** 답한다 |
| 12 | 하루 지출 `CHAT-10` | 오늘·어제·그제·`M월 D일` + 얼마·썼·지출·수입 | 카테고리를 함께 말하면("오늘 식비") 그날·그 카테고리의 **목록+합계**로 답한다 |

- **"얼마"는 단독 트리거가 아니다.** "이거 얼마야"처럼 무관한 문장을 잡지 않기 위함이다

**R4. 답변 규칙**
1. **첫 줄에 조회 범위를 밝힌다**(`2026년 9월`, `최근 7일`, `스타벅스` 등). 사용자가 해석된 기간을 바로 확인할 수 있어야 R2의 해석이 틀렸을 때 알아챈다
2. 금액은 `lib/money.ts` 포맷 + "원". 증감은 `+`/`-` 부호와 소수 첫째 자리 %로 쓴다
3. **예측·이상치 값은 서버 응답을 그대로 쓴다.** 과거 달의 예상 지출을 물으면 "끝난 달이라 확정 지출"로 답하고, `forecast`가 `null`이면 `STAT-07` 문구를 그대로 쓴다
4. **이번 달을 다른 달과 비교할 때는 "아직 N일째"라는 단서를 붙인다.** 진행 중인 달과 끝난 달을 비교하면 거의 항상 "줄었다"가 나오기 때문이다
5. 기준 금액이 0이면 증감률을 계산하지 않고 "기준 달엔 지출이 없었어요"라고 쓴다(0으로 나누지 않는다)
6. 목록 답변: 각 줄 `날짜 · 카테고리 · 거래처 · ±금액`(거래처 없으면 생략). 받아온 건수보다 전체가 많으면 "전체 N건 중 M건"을 밝히고, 끝에 같은 필터의 `/transactions` 딥링크를 붙인다
7. 합계는 **전체 건수가 받아온 건수 이하일 때만 "합계"**라고 쓰고, 넘치면 "최근 M건 합계(전체 N건)"로 쓴다 — 일부 합계를 전체처럼 말하지 않는다
8. 데이터가 없는 경우의 문구를 의도별로 구분한다(지출 없음 / 예산 미설정 / 이상치 없음 / 월초라 판단 보류)
9. 목록은 기본 5줄(`N건`을 말하면 N줄, 최대 20)만 보여준다. 합계를 물으면 20건까지 받아와 합산하되 화면에는 같은 줄 수만 보여준다
10. 필요한 조회가 실패하면 "확인하고 있어요"에서 멈추지 않고 "데이터를 불러오지 못했어요"로 끝낸다

### 5.2 `/login`
- 이메일·비밀번호 입력, "로그인" 버튼 — `AUTH-04`
- 회원가입 링크
- 실패 시 인라인 에러 메시지 (5.1 에러 문구 매핑 적용)

### 5.3 `/signup`
- 이메일·비밀번호·닉네임 입력 — `AUTH-01`
- 비밀번호는 **제출 전에 6자 이상 / 72바이트 이하를 인라인으로 안내**한다 — `AUTH-02`
  - 한글은 1자가 3바이트임을 안내 문구에 포함한다
- 이메일 중복 시 인라인 안내 — `AUTH-03`
- 가입 성공 시 JWT 저장 + **기본 카테고리 9개가 서버에서 함께 생성**된 상태로 `/dashboard` 이동 — `AUTH-05`

### 5.4 `/dashboard`
**월 선택** — `STAT-01`
- `◀ 2026년 9월 ▶` 형태. 선택한 월은 URL 쿼리(`?ym=2026-09`)로 관리해 뒤로가기가 동작한다
- 미래 달로는 이동할 수 없다

**요약 카드** — `STAT-01`
- 총수입 / 총지출 / 잔액 3개 카드. 잔액이 음수면 빨강

**예측 카드** — `STAT-04`, `STAT-07`
- "이번 달 이 속도면 **2,610,000원**을 쓰게 돼요"
- 보조 문구: "15일 경과 · 최근 3개월 기준"
- **과거 달을 보고 있으면 예측 카드를 숨긴다.** 끝난 달의 "예상"은 의미가 없다
- 데이터 부족 시: "예측하려면 데이터가 조금 더 필요해요" — `STAT-07`

**이상치 안내** — `STAT-05`
- "식비가 평소보다 34% 높아요" 형태로 최대 3개
- 경과 7일 미만이거나 해당 없으면 카드를 렌더링하지 않는다

**고정지출 카드** — `STAT-06`
- 감지된 항목의 거래처·금액·연속 개월 수·최근 날짜, 그리고 합계
- **"등록" 버튼을 두지 않는다.** 이 카드는 읽기 전용 안내다
- 별도 API로 로드되므로 이 카드만 따로 스켈레톤을 보여준다

**차트** — `STAT-02`, `STAT-03`, `BUD-03`, `BUD-04`
- 카테고리별 지출 차트(도넛 · 막대 · 트리맵 중 사용자가 탭으로 선택, 기본 도넛. 탭 이름은 도넛이 "원형") + 금액·비율 — `STAT-02`
- 예산 소진율 막대. 초과 카테고리는 막대와 수치를 빨강으로 — `BUD-03`, `BUD-04`
- 일별 히트맵(달력 7열 격자). 지출액에 따라 배경 농도 4단계. 첫 주·마지막 주의 빈 칸에는 이전·다음 달 날짜를 옅게(투명도 40%) 채우며 누를 수 없다 — `STAT-03`
  - 1일의 요일에 맞춰 앞쪽 칸을 비운다
  - 각 칸에 날짜와 금액을 툴팁/보조 텍스트로 제공한다

**빈 상태** — `STAT-08`
- 거래가 없는 달은 에러가 아니라 모두 0인 정상 화면이다. 차트 자리에 "이 달에는 기록이 없어요"를 보여주고 월 이동 버튼은 그대로 동작한다

### 5.5 `/transactions`

**퀵 입력 바 (화면 최상단)** — `TXN-01` ~ `TXN-05`
- 필드: 구분 토글(수입/지출) · 금액 · 카테고리 select · 날짜(기본 오늘) · 거래처 · 메모
- **최근 사용 카테고리 3개를 버튼으로 노출** — `TXN-03`
  - 별도 API를 만들지 않고, 이미 받아온 목록 앞쪽에서 중복 제거해 뽑는다
- 저장 시 버튼에 로딩 상태 표시. 성공하면 목록 맨 위에 추가되고 **폼은 비워지되 날짜·구분은 유지** — `TXN-02`
- 카테고리가 하나도 없으면 폼을 비활성화하고 `/settings/categories` 링크를 안내한다
- **낙관적 업데이트를 하지 않는다.** 서버가 채우는 `id`·카테고리 조인 결과가 있어 임시 데이터와 어긋난다 (`CLAUDE.md` 9장)

**영수증으로 등록** — `TXN-13`
- 퀵 입력 바 옆에 "영수증 첨부" 버튼으로 이미지 파일을 첨부한다(촬영 UI는 만들지 않는다 — 기기 사진 앱/파일 선택으로 고른 이미지를 그대로 첨부하는 것으로 충분하다)
- 파일을 첨부하면 인식 중 로딩 상태를 보여주고, 완료되면 **퀵 입력 바 필드가 채워질 뿐 자동 저장되지 않는다** — 사용자가 값을 확인·수정한 뒤 기존 "저장" 버튼을 눌러야 등록된다
- 인식하지 못한 필드는 비워두고, 인식된 필드만 채운다. 전체 인식 실패 시 "영수증을 읽지 못했어요. 직접 입력해 주세요"를 안내한다
- 카테고리는 **이름으로 매칭**한다. 매칭되는 카테고리가 없으면 선택하지 않은 상태로 두고 사용자가 직접 고른다(CSV 가져오기처럼 자동 생성하지 않는다)

**필터 · 검색** — `TXN-07`, `TXN-08`
- 기간(from/to) · 구분 · 카테고리 · 키워드. 전부 URL 쿼리로 관리
- 키워드는 거래처와 메모를 함께 검색한다

**목록** — `TXN-06`, `TXN-09`, `TXN-10`
- 날짜 내림차순, 페이지당 20건
- 각 행: 날짜 · 카테고리 배지(색) · 거래처(위치가 있으면 아이콘) · 금액(수입 초록 / 지출 빨강) · 삭제 버튼
- **행을 누르면 페이지 이동 없이 팝업으로 수정 화면이 열린다** — `TXN-09`. `/transactions/[id]` 페이지는 직접 링크로 들어왔을 때를 위한 대체 경로로 남는다
- 삭제는 **낙관적 업데이트**로 즉시 사라진다 — `TXN-10`
- 마지막 항목 삭제로 현재 페이지가 비면 이전 페이지로 이동한다(`page > 0`일 때)
- 삭제된 카테고리가 붙은 거래는 배지 옆에 "삭제됨" 표시 — `CAT-03`

**위치 표시** — `TXN-14`
- 퀵 입력 바와 팝업 편집 화면의 거래처 입력 옆에 위치 아이콘이 있다. 누르면 카카오맵 검색 팝업이 열려 지점을 고르고, 좌표가 저장되며 비어 있던 거래처 필드는 고른 지점명으로 채워진다
- 이미 위치가 있는 상태에서 다시 골라도 좌표와 거래처명이 새로 고른 지점으로 갱신된다
- 위치를 지정한 거래는 목록 행에 작은 지도 아이콘이 뜬다. 누르면 그 좌표를 중심으로 한 읽기 전용 지도 팝업이 열린다
- 위치가 없는 거래에는 아이콘이 뜨지 않는다(회귀 확인 대상)

**빈 상태 / 검색 결과 없음** — `UX-02`, `UX-03`
- 거래 없음: "아직 기록이 없어요" + 퀵 입력 바로 포커스 이동
- 검색 결과 없음: "조건에 맞는 내역이 없어요" + 필터 초기화 버튼

### 5.6 `/transactions/[id]`
> 목록에서는 이 화면 대신 **팝업(5.5 「목록」 참조)**으로 수정한다. 이 페이지는 직접 링크·북마크로 들어왔을 때를 위한 대체 경로로 남아 있다.
- 진입 즉시 **모든 필드가 편집 가능한 상태**다. 보기/편집 모드를 나누지 않는다 — `TXN-09`
- `/transactions`의 퀵 입력 바와 **같은 폼 컴포넌트(`TransactionForm`)를 재사용**하고, 초기값 유무와 삭제 버튼 노출로만 구분한다
- 자동 저장 없이 "저장" 버튼으로 반영한다
- **변경 사항이 있는 상태로 이탈하려 하면 확인 대화상자**를 띄운다 — `TXN-09`
  - 새로고침·탭 닫기 / 화면 내 버튼 / 브라우저 뒤로가기 **세 경로를 모두 막는다** (`CLAUDE.md` 9장)
  - 금액의 `dirty` 판정은 **콤마를 제거한 원본 값끼리** 비교한다
- 저장 실패 시 폼 내용을 유지한 채 에러를 표시한다 — `TXN-11`
- 없는 id이거나 타인 소유이면 "거래 내역을 찾을 수 없습니다" 화면 + 목록으로 가기 버튼

### 5.7 `/budgets`
- 월 선택(대시보드와 동일 UI), **지출 카테고리 전체가 행으로 나열**되고 각 행에 금액 입력 — `BUD-01`
- 비우거나 0이면 미설정 — `BUD-02`
- "저장" 버튼 하나로 전체를 upsert한다. 개별 저장 버튼을 두지 않는다
- 저장 후 대시보드 소진율이 즉시 갱신되도록 `['stats']` 캐시를 함께 무효화한다

### 5.8 `/settings/categories`
- 수입/지출 탭으로 구분해 목록 표시 — `CAT-01`
- 각 행: 색 점 · 이름 · 표시 순서 · 수정/삭제 버튼
- 추가 폼: 이름 + 색 선택(§8 팔레트에서 고르거나 직접 입력) — `CAT-01`
- **구분(수입/지출)은 수정 폼에 두지 않는다** — `CAT-02`
- 이름 중복 시 인라인 안내 — `CAT-04`
- 삭제 시 "이 카테고리를 쓰는 과거 내역은 그대로 남습니다"를 확인 문구에 포함 — `CAT-03`

### 5.9 `/data`
**내보내기** — `CSV-01`, `CSV-02`
- 기간 선택(기본: 이번 달) → "CSV 내려받기"
- 파일명 `moneylog_2026-09.csv`
- **UTF-8 BOM을 포함해 Excel에서 한글이 깨지지 않는다** — `CSV-02`

**가져오기** — `CSV-03` ~ `CSV-07`
- 파일 선택 → 업로드 → 결과 표시
- 결과: "42건 등록, 3건 실패" + 실패 행 목록(행 번호 + 사유) — `CSV-04`
- 형식 안내를 화면에 표로 보여준다(헤더 6열, 구분은 `수입`/`지출`, 카테고리는 이름으로 매칭)
- 상한 안내: 1MB / 5,000행
- **엑셀이 되돌려준 파일도 읽는다** — CP949 인코딩, 금액의 천단위 콤마, `2026.09.14` 날짜를 모두 인식한다 — `CSV-07`
- **중복 안내**: "이미 가져온 파일을 다시 올리면 중복 등록됩니다" — 중복 검사를 하지 않는다(1장 비목표)
- 성공 시 `['transactions']`·`['stats']` 캐시를 무효화한다

## 9. 향후 확장 후보 (범위 밖)

우선순위 순으로 기록만 해둔다. 이번 MVP에서는 구현하지 않는다.

1. **구글 OAuth2 로그인** (`AUTH-09`)
2. **배포** — 방식 미정. AWS 조합(Amplify + EC2 + RDS)을 전제로 제약만 지켜둔 상태
3. **LLM 소비 리포트** (`STAT-09`) — 집계 결과를 Claude API에 넘겨 자연어 리포트·절약 제안 생성
4. **정산 주기(급여일 기준 집계)** — 집계 기준을 달력 월에서 `[매월 D일 ~ 다음달 D-1일]`로 바꾼다. 급여일이 25일인 사용자에게 달력 월 집계는 생활 주기와 어긋난다.
   > **지금 도입 비용이 낮은 구조라는 점을 기록해둔다.** 기간을 파생값으로 두는 것(=`transactions`에 기간 키를 저장하지 않음)이 이 기능의 전제인데, 우리는 `txn_date`만 갖고 있어 이미 충족한다. `budgets.year_month CHAR(7)`도 그대로 기간 키로 쓸 수 있다. 바뀌는 것은 **조회 범위 계산과 API 파라미터뿐**이고 스키마·인덱스는 유지된다. 다만 모든 집계·예산 쿼리가 이 기준을 타므로, 도입 시점에는 `/stats`·`/budgets` 전부를 함께 고쳐야 한다.
5. **삭제 취소(휴지통)** — 거래·카테고리를 Soft Delete하면서 복원 경로가 없다. 데이터는 이미 `deleted_at`으로 남아 있으므로 목록 필터 + 복원 API만 얹으면 된다
6. **영수증 사진 첨부(보관)** — 인식(`TXN-13`)과 별개로, 촬영한 원본 사진을 거래에 첨부해 보관하는 기능. 로컬 스토리지로 먼저 완성 후 S3 전환
7. 반복 거래 자동 등록 (고정지출 감지를 "등록"으로 승격)
8. 예산 초과 알림 (`BUD-05`)
9. 결제수단(카드/현금/계좌) 분류, 태그
10. **거래 분할(Split)** — 한 거래를 카테고리별 하위 항목으로 쪼갠다. ATM 출금 50,000원에 점심 12,000·택시 8,000을 기입하면 미기입 30,000원이 원래 카테고리에 남는 식이다. 현금 지출을 다루는 실용적인 모델이며, **하위 항목에 날짜를 두지 않고 부모 거래일에 귀속**시키면 `총지출 = 카테고리 합계`가 항상 성립한다
11. 연간 리포트, 전년 동월 비교
12. 카테고리 계층 구조 (대분류/소분류)
13. 자산/부채 및 순자산 추적
